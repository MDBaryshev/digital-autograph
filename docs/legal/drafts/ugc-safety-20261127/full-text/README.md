## Точная воспроизводимость

Из корня репозитория:

```powershell
node docs/legal/drafts/ugc-safety-20261127/full-text/build.mjs --check
```

Команда только читает. Она проверяет исходные тексты и предложенные положения
по старому manifest EGO-209, извлекает дословные блоки из
`../proposed-clauses.md`, применяет 16 замен или вставок и сравнивает
ожидаемые полные файлы и `edits.json` с фактическими. Каждый точный anchor
должен встречаться один раз; отсутствие или неоднозначность останавливают
проверку. Обратное применение каждой карты изменений восстанавливает
все четыре исходных тела полностью. Допустимое преобразование исходного
checkout — только CRLF → LF; иные изменения вне карты не допускаются.
Маркеры `prettier-ignore-start` / `prettier-ignore-end` защищают договорное
тело review-копии от автоматического изменения исходной вёрстки; они находятся
вне юридического текста и не являются условием договора.

Для повторной сборки тех же review-копий используется та же команда без
`--check`. Она пишет только четыре перечисленных новых файла и `edits.json`
в этой папке. `edits.json` содержит source path/hash, ссылку на точный
заголовок блока предложений, exact `before`/`after` каждого изменения
и отдельную операцию `preserve-no-edit`.

Инструкция EGO-209 «При подготовке полной редакции сохранить раздел об изменении
Соглашения» — редакционное требование, а не новый договорный пункт. Поэтому
исходный раздел «Изменение настоящего Соглашения» сохранён дословно;
сама инструкция не вставлена в договорное тело. Это решение отдельно
согласовано при агентской проверке сборки.

Существующие canonical/public/DOCX, реестр публикаций и прежний manifest
EGO-209 не изменяются. Отдельный `manifest.json` фиксирует хеши исходников,
полных проектов и инструментов. Для его проверки без записи файлов:

```powershell
node docs/legal/drafts/ugc-safety-20261127/full-text/verify-manifest.mjs --check
```

`git_blob_sha256` относится к точным байтам Git blob закреплённого base commit;
`checkout_raw_sha256` — к точным байтам локального checkout при подготовке
manifest; `lf_sha256` — к UTF-8 после единственного преобразования CRLF → LF.
Проверка бинарных источников требует точного совпадения байтов; для текста
допускается только указанное различие окончаний строк. Manifest не включает
собственный хеш во избежание рекурсии; его хеш передаётся отдельно при ревью.
