# Стена Supcube в Telegram

Telegram Bot API 10.4 поддерживает HTML-виджеты внутри сообщений. Виджет
работает без сетевого доступа: бот отправляет фиксированный HTML через
`sendWidget`, а затем меняет общее состояние через `editSharedWidgetData`.
Открытый виджет следит за изменениями через `watchPublicData`. Параметр
кэша здесь 30 секунд, поэтому статус в чате может отставать от сайта.
[Документация виджетов](https://core.telegram.org/bots/widgets) ·
[Изменение состояния](https://core.telegram.org/bots/api#editsharedwidgetdata).

В production Telegram описывает только личный чат с ботом. В канале нельзя
публиковать виджет напрямую, а группы, inline-режим и пересылка доступны
для проверки на тестовом сервере. Перед пилотом нужно подтвердить доступ к
`sendWidget` для конкретного бота: сопровождающий Bot API сообщил об
ограничении и для обычных ботов. Для публикации стены пользователем остаётся
обычная ссылка на неё. На опубликованной стене «Поделиться ссылкой в Telegram»
открывает выбор чата или канала. [Ограничения Telegram](https://core.telegram.org/bots/widgets#availability) ·
[Отправка ссылки](https://core.telegram.org/widgets/share) ·
[Ответ сопровождающего Bot API](https://github.com/tdlib/telegram-bot-api/issues/947#issuecomment-6862125233).

В `packages/integrations/src/telegram-wall-widget.ts` подготовлены шаблон и
тела двух запросов. Они принимают уже разрешённое публичное представление
стены, передают заголовок, занятость 10 мест и ссылку с настроенного HTTPS
origin. При закрытии публикации новое состояние показывает «Стена недоступна».
Изображения автографов, идентификаторы аккаунтов и данные личной сессии не
участвуют. Отправка и обновление пока не подключены к работающему приложению.

Для пилота:

1. В тестовом Telegram подтвердить операции отправки, обновления и закрытия
   виджета. Пройти просмотр двумя получателями и измерить задержку обновления.
2. Связать действие владельца со стеной через серверную авторизацию и
   подтверждённый чат с ботом. Хранить `widget_id` и монотонную ревизию на
   сервере. Перед каждой отправкой читать актуальное публичное состояние
   стены и проверять право на её публикацию.
3. Обновлять карточку после изменения стены или места через фоновую задачу.
   Объединять быстрые изменения, не превышать одно обновление в секунду на
   виджет и не повторять неопределённый результат создания без сверки.
   Ошибки Telegram не влияют на операции стены.
4. Проверить закрытие публикации, устаревшие обновления, недоступность API
   и возврат к обычной ссылке. Перед включением согласовать правила отзыва
   и отображение данных в чате.
