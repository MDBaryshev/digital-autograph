# OpenRouter autograph features (EGO-176)

Two server-only features, disabled by default. They do not deploy or activate payments, legal publication or creator admission.

## Configuration and privacy

Supply `OPENROUTER_API_KEY` through the API server's private environment, never a browser variable or a committed file. Set `OPENROUTER_IMAGE_MODEL` to an explicitly chosen model served by the dedicated Images API and `OPENROUTER_MODERATION_MODEL` to a vision model supporting JSON output. No model name is guessed. Independently enable `AI_AUTOGRAPH_GENERATION_ENABLED=true` and/or `AI_AUTOGRAPH_MODERATION_ENABLED=true`. Incomplete enabled configuration fails startup and `--check-config`, with values redacted.

Moderation also requires `AI_MODERATOR_USER_ID`: a dedicated, clearly named AI service account with an existing platform moderator role. No code creates a user or grants a role. Do not reuse a real person's identity. Ordinary role/status checks run before disclosure and again at decision time. Provider output is untrusted. Original uploads, signed URLs, object keys, cookies and user IDs are never sent to OpenRouter. Only the owner-approved cleaned PNG is sent for moderation; a submitted nickname is sent for generation. The UI explains these transfers. Before enabling on real data, configure the deployment's privacy notice, provider agreement and restricted API key budget. Both endpoints disable provider fallback. Moderation's Chat Completions requests require `provider.data_collection=deny`. Images API does not accept that field: configure and verify its data-collection/privacy policy in the OpenRouter account before enabling generation. The two privacy mechanisms are not interchangeable.

Endpoints are fixed to HTTPS OpenRouter: generation uses `POST /api/v1/images`; moderation uses `POST /api/v1/chat/completions`. Redirects are refused; response reads are bounded to 8 MiB for images and 4 MiB for moderation, with a 60-second network deadline per call. No model-generated remote URL is fetched. Generation accepts exactly one inline PNG/JPEG/WebP per call, at most 4 MiB decoded input and 16 megapixels. The declared MIME type must match the byte signature and decoder format; corrupt, animated and unsupported inputs fail the batch. Sharp applies orientation, strips source metadata, and resizes without enlargement to at most 1024 pixels per side. Each returned PNG is at most 2 MiB. Existing private upload/processing checks still run on the explicitly selected image. Errors/logs never include the key, nickname, image or provider diagnostics.

## Generation

A signed-in user explicitly requests three simple youthful styles by nickname: quick everyday pen handwriting, casual marker lettering, and a compact rounded nickname tag. Prompts avoid formal calligraphy, ornamental flourishes and large monograms; exact case, Cyrillic ё, digits and underscores are requested but must still be checked by the owner. The shared prompt builder in `packages/integrations/src/autograph-generation-prompts.ts` is used by the server and evaluation runner. Each Images API request asks for one square image; explicitly selecting `openai/gpt-image-2` uses the evaluated `quality=low` setting. Other configured models use their default quality and must support this endpoint and request shape.

The POST is protected by the existing Origin and first-use guards and returns 202 immediately; polling GET requests are scoped to that same owner and use no-store. Request UUID plus nickname hash prevent duplicate dispatch. There are three sequential image calls, with no automatic provider retries. A failed or invalid later image fails the entire batch; partial choices are not returned or automatically regenerated. The UI never uploads, approves or places an image merely because it was generated or selected. Selecting a variant provides a PNG blob to the existing `photo` private upload/processing/cleaned-preview/owner-approval flow. Drawing and photo editing remain available.

PostgreSQL serializes admission across API instances: at most 3 batches per user per UTC day and 20 batches globally (up to 60 image calls). These are request budgets, not a currency cap; configure a provider-side spending limit. Pending and failed batches consume budget. A crash/unknown result is not automatically retried; the same UUID cannot trigger another charge. Successful results can be replayed by their owner for one hour. Image results are removed by the running API cleanup cycle after an hour; metadata remains for quotas. Nicknames themselves are not persisted. An API crash can leave a pending job; the UI times out and retains drawing as fallback. After an uncertain outcome, an operator must inspect before authorizing any new spend; changing the nickname explicitly starts a new budgeted request.

## Automated moderation

The API runs a bounded one-item cycle every ten seconds with no overlapping cycles per process. Durable uniqueness on the cleaned asset prevents duplicate provider dispatch across instances, even after a crash or actor configuration change. AI request/model/asset/policy-version/verdict evidence is saved before attempting an ordinary moderation decision. Completed moderation evidence is immutable in PostgreSQL. It is separate from human evidence and never portrayed as a human review.

Only a valid approved/rejected verdict with confidence >= 0.95 may enter the existing transactional decision path. Manual, malformed, truncated (`finish_reason=length`), lower-confidence, oversized-image and provider-failure cases remain in the manual queue. There is no automatic approval on outage. The eight existing rejection codes are the only accepted reasons; prompts reject real bank/legal/passport samples without claiming handwriting/identity verification. The numerical threshold is a conservative routing rule, not calibrated accuracy evidence: review representative labeled samples before production activation. A concurrent human decision wins through existing row locking/immutable evidence. Model results are recorded as assessments; a recorded result does not by itself prove it was applied. No Slot, Order, financial ledger or refund writer is added.

At most 200 moderation attempts per UTC day globally; uncertainty stays charged and is not automatically retried. A dedicated actor's access can be revoked to stop future moderation. Disabling the feature prevents new cycles; stop/restart API instances and wait for any in-flight cycle before changing policy. A shutdown waits for bounded running calls and never applies a late verdict once shutdown begins.

## Offline preparation and bounded live model comparison

`scripts/evaluate-openrouter.mjs` uses the dedicated `POST /api/v1/images` API for GPT Image 2 and Nano Banana 2.1 with the server's shared prompts and request parameters. It accepts inline PNG/JPEG/WebP and normalizes bytes with bounded Sharp decoding. No returned URL is fetched. The Image API does not accept Chat Completions' `provider.data_collection`; its privacy settings must be configured in the OpenRouter account. This comparison does not activate production features. Request and response shapes are documented in [OpenRouter's Images API guide](https://openrouter.ai/docs/guides/overview/multimodal/image-generation).

Run `node scripts/evaluate-openrouter.mjs` to print a plan without credentials or network. The default pilot makes 18 image requests (three synthetic nicknames, three styles, two models) and 12 classification requests (six synthetic smoke samples, two models). These simple samples test the protocol, latency and obvious false positives; they do not evaluate the full content policy. For a substantive moderation comparison, pass `--moderation-manifest /private/labeled-samples.json`: an array of `{ "path": "relative-image.png", "expected": "approved|rejected|manual" }`, at most200 owner-authorized labeled samples.

Use a separate test key with a provider-side spending cap. Supply it only through `OPENROUTER_API_KEY`, or the local ignored0600 `.env.openrouter-eval` file. Then `node --env-file=.env.openrouter-eval scripts/evaluate-openrouter.mjs --run` starts the pilot. Outbound HTTPS to `openrouter.ai` must be allowed in the managed environment. The runner never retries a paid call, stops if cost is missing, and stops further requests once reported aggregate usage reaches$3; only the provider-side cap bounds actual charges, including uncertain outcomes. Reports and images use private filesystem permissions outside the repository. Results include latency and reported cost, a local HTML gallery and a ratings CSV for spelling/readability/style. Human ratings and a representative labeled moderation corpus are necessary before choosing a production winner. No live run has occurred without a configured key and network access.

### Local synthetic pilot, 2026-11-03

A private pilot compared nine original-style images per model: GPT Image 2 low quality averaged about $0.0062/image and 12.6 seconds; Nano Banana 2.1 averaged about $0.0361/image and 13.0 seconds. A further nine GPT Image 2 images used the new casual direction at about $0.007/image. These are observed costs for these settings, not guaranteed prices or a broad quality ranking. Images, prompts, credentials and individual reports remain outside Git.

The updated server adapter also completed one live synthetic-nickname batch: exactly three Images API requests returned three normalized PNG choices, with reported aggregate cost about $0.021. This verifies the adapter/provider contract, not a deployed authenticated workflow. HTTP tests separately cover the real adapter with provider fixtures, owner-scoped result reads, completed-request replay and failed-request handling; UI tests cover explicit PNG selection into the existing upload flow.

Moderation is highly sensitive to the prompt and token limit. A separate nine-case check using the production prompt and 300 tokens returned valid verdicts in 9/9 cases for Gemini 3.1 Flash Lite; Gemini 3.5 Flash returned 7/9 length-truncated unusable results. Flash Lite matched eight labels; the remaining printed monogram was rejected by both models despite the initial expected-approved label. Clarify that product boundary before treating the label as authoritative. The short-prompt runner uses a different contract and is only a protocol smoke check. These synthetic samples do not establish safety accuracy; the provisional model choices do not enable either feature or authorize rollout.
