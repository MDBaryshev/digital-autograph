# Wall invitations

Every public Wall can be invited to before its first placement. The invitation is the current web origin plus `/walls/<uuid>`; no session, user ID, referral query or slot ownership is encoded. Copy/native share/manual selection do not create placement share records or send a message. Native-share cancellation stays quiet. Existing placement/final-Wall sharing, consent, revocation and attribution remain separate.

QR generation is browser-local with pinned `qrcode-generator` 2.0.4. The code uses a four-module quiet zone, black modules on white in both themes, and can be downloaded as an SVG containing only fixed numeric geometry. No QR service or third-party request receives the URL. Independent `jsQR` decoding tests validate production, loopback and international-domain URLs. Browser E2E also decodes the actual downloaded SVG after rasterization.

`GET /walls/:id/invite-card?locale=ru|en` reads through ordinary public Wall visibility, returning 404 for draft/archived/unknown Walls. The 1200×630 PNG contains bounded public title/creator text, ten numbered places and the three podium crowns. It never reads or fetches original autographs, private provider candidates, avatars, covers or external media. XML-invalid characters and markup are escaped/removed. At most two images render concurrently per API process; busy requests receive 503/Retry-After. Responses use no-store; social networks may maintain their own caches after a Wall changes visibility.

Wall OG and Twitter metadata point only to the configured public API card URL. Invitations carry no eligibility, price, payment or permission authority, and create no database writer or migration. Tests cover copying and native cancellation, manual fallback, independent QR decoding, hostile Unicode/markup, public visibility and card dimensions. Physical phone scanning and previews inside individual social applications remain device/channel acceptance checks; synthetic Chromium is not a claim of those checks.
