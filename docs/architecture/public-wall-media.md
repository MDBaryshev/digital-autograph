# Public Wall media and Free Claim UX

## Placement-based media

The stable public URL is `GET /public/placements/:placementId/autograph`. It works without authentication and is independent of Free Claim source or Wall claimability. The API checks that the Placement is active, its Wall is public (scheduled/live/paused/ended), the Autograph belongs to its active User, and the Autograph is `ready`. Placement and Wall rows are held with shared locks while the evidence is resolved. The shared verifier requires owner approval, its exact uploaded cleaned Asset, an approved Moderation Decision and valid PNG metadata. The service reads only the private cleaned object, within its 10 MiB limit, and verifies length and signature. After storage I/O it resolves the current permission again and requires the same derivative key and verified size. An account disable, Wall archive or changed resolution that commits during the read withholds the already-read bytes. It never reads or falls back to the original. The bucket remains private and the browser never sees storage keys or owner preview URLs.

Missing, ended, nonpublic, inactive-owner or inconsistent media returns public 404 with no internal reason. Evidence inconsistency, missing private object, other storage failure, and invalid object bytes are distinguishable in internal logs by Placement ID and reason only. Success responds with `Content-Disposition: inline`, `X-Content-Type-Options: nosniff`, and `Cache-Control: no-store`; failures also use `no-store`. This removes the former 60-second public cache permission for new responses. Rollout must separately account for responses cached under the old policy; previously downloaded or copied bytes cannot be recalled. The final authorization check does not retract bytes already delivered before a later state change.

`GET /walls/:id` joins active Placement, Autograph, its active owner, approval, cleaned Asset, and moderation evidence in one query. It emits only a relative `mediaPath` when that evidence is consistent. Occupancy always follows active Placement, so unavailable media produces `occupied=true` and `mediaPath=null`. Disabling a signer does not free a Slot, rewrite decisions or trigger financial changes. Missing storage is detected by the image endpoint; the page falls back to an unavailable state if the image fails. Wall JSON uses `Cache-Control: no-store` so manual refresh observes current occupancy. The Wall API does not download images or disclose User, Autograph, evidence, Asset, or storage identifiers. These guards do not implement reports, a granular moderation overlay, account-management actions, appeals or hiding every public profile/share representation.

## Owner selection and claim flow

Authenticated `GET /autographs?status=ready` returns up to 30 recent owner choices after evidence verification. A bounded 50-row candidate scan excludes inconsistent ready records. Each item contains ID, source, creation time, and moderation time; no storage metadata. The browser uses the existing owner-only preview endpoint for the selected Autograph. Signed preview URLs stay in component memory, are refreshed before expiry, and are never used for public Wall images.

Private selection preview state is keyed by API origin and the selected ready
Autograph. A parent selection change removes the old image before the new read
finishes. Missing/invalid choices do not issue a preview read. Reads include a
10-second deadline for fetch and body parsing, cancellation on unmount/selection
change, and explicit GET retry after errors; late reads and image-error events
cannot replace the current preview. Expired images are hidden, including when
renewal fails. Preview loading never disables the radio choices or adds a claim
eligibility condition; the existing backend still authorizes every claim.

The server renders initial public Wall data using `API_INTERNAL_URL`. The browser uses `API_PUBLIC_ORIGIN` for refresh, auth, preview, claim, and public media. The page works anonymously and offers the existing Google/Telegram login flow with a fixed `/walls/<id>` return path when an empty Slot is selected. Authenticated Users without ready Autographs are directed to `/autograph/create`. A User selects a ready Autograph, selects an empty Slot, sees the one-use warning and confirmation, then sends the existing Free Claim request. Both 201 and exact-retry 200 are success; the page refetches the Wall before displaying the new occupied Slot. `SLOT_OCCUPIED` refreshes without trying another Slot, `FREE_CLAIM_ALREADY_USED` disables further attempts, and `WALL_NOT_CLAIMABLE` refreshes and disables the flow. Manual Refresh provides a low-cost update path without push infrastructure.

Browser timing only controls presentation. PostgreSQL remains authoritative for Wall eligibility, Slot occupancy, and Autograph evidence. Scheduled, paused, and ended Walls remain readable without mutation controls; draft and archived Walls remain 404. Owner preview and API session requests use existing cookie auth and origin protection. Browser web/API origins must remain compatible with the existing SameSite cookie setup; local MinIO and production S3 need CORS for browser preview, but never public bucket access.
