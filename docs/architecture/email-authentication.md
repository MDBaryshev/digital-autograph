# Вход и регистрация по почте

При регистрации пользователь указывает адрес и получает одноразовую ссылку.
После перехода он задаёт пароль. PostgreSQL создаёт аккаунт и запись о
подтверждённом адресе в одной транзакции. Для входа используются тот же адрес
и пароль. Восстановление подтверждает владение почтой по той же схеме,
обновляет пароль и отзывает прежние сессии.

Ссылка действует 30 минут. Её случайный токен хранится в PostgreSQL как
SHA-256. Страница читает токен из фрагмента URL, сразу убирает его из истории
и передаёт серверу в теле запроса при установке пароля. Сервер проверяет срок
и одноразовость внутри транзакции. Пароль хранится в виде хеша scrypt с солью.
Параллельный вход со старым паролем проверяет его хеш под той же блокировкой
аккаунта, которую использует восстановление.

После регистрации или восстановления ссылка возвращает пользователя на
исходную страницу, если она входит в список разрешённых. Для остальных
страниц открывается кабинет. Данные заказа и брони в письмо не передаются.

Вход выдаёт обычную сессию Destka. Проверка Origin применяется ко всем
операциям по почте. PostgreSQL считает запросы отдельно по каждой операции
и адресу. Запрос сверх лимита адреса не расходует общий лимит операции.
Запрос письма возвращает одинаковый ответ
для существующего и свободного адреса. API обрабатывает доставку в фоне,
ограничивает число одновременных отправок и позволяет повторить запрос
после минутного интервала.

## Подключение UniSender Go

1. Примените миграцию `0030_email_auth` вместе с предыдущими миграциями и
   установите права из `deploy/postgres-runtime.sql`. API использует таблицы
   подтверждений, учётных данных и лимитов. Воркер удаляет просроченные
   подтверждения и счётчики.
2. Подтвердите в UniSender Go домен отправителя и настройте DKIM по записям
   провайдера. Для транзакционных писем проекту нужно разрешение на отправку
   с `track_links=0` и `track_read=0`. UniSender Go указывает, что его
   включает поддержка. [Справочник UniSender Go](https://godocs.unisender.ru/web-api-ref)
3. Укажите на сервере `AUTH_EMAIL_FROM`, `UNISENDER_GO_API_KEY` и
   `EMAIL_AUTH_ENABLED=true`. Ссылка строится от `WEB_ORIGIN`. Вход по
   почте появляется на сайте после запуска API с этой конфигурацией.
4. Проверьте доставку на тестовый адрес. Ответ `success` API UniSender Go
   подтверждает приём письма в очередь. Реальная доставка проверяется в
   почтовом ящике и в кабинете UniSender Go.

API отправляет одно письмо через `email/send.json` по HTTPS. Ключ передаётся
в заголовке `X-API-KEY`. Проверка ответа учитывает отклонённых получателей.
Логи доставки содержат фиксированное событие. [Справочник UniSender Go](https://godocs.unisender.ru/web-api-ref)
